## Observations

**t+0 — false alarm, mine.** The actuation check flagged "motor not running" at
t=103 s. The profile schedules **0 rpm until t=120 s**; the check did not allow for a
legitimately zero target. Corrected before arming — the alarm now requires
`rpm_target > 0`. Worth remembering: a monitor that cries wolf gets ignored, which
costs more than having no monitor.

**t+2 min — actuation confirmed.** `rpm_target=100`, drive at 1.68 Hz (100/59.5 ✓),
`vfd_is_running=True`, `omron_pv_c=46 °C`. RS485 healthy — the failure mode from this
morning (API holding `/dev/ttyUSB0`, run silently stationary) did **not** recur, even
though the run was started from the UI after a backend restart, which is exactly the
sequence that triggered it.

**t+8 min — tacho artifact reconfirmed.** `rpm_meas=679.23` against a true 100 rpm:
**+579 rpm**, matching the +582 rpm constant offset characterised in ticket 0002.
